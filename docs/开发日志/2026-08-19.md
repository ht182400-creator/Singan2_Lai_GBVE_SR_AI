## M0.1 / M0.2 解析层完成（已验证 + 测试全绿）

**关键逆向发现**（决定 POC 正确性）：
1. 图像尺寸硬编码 88×186（文件内 width/height 字段为 0，已采样确认）。
2. `MM1_Side`（type=5）是 S2 算法输入：每波段 **8bit/像素**，块 = 16368 数据 + 24 填充 = 16392 字节；13 波段拼成 `global_onedat`（213096 字节）。
3. `ReadImgDataNew` 的 memcpy 布局：波段 k 按 `(16368+24)*k` 间隔取，k→Img 映射非顺序（k0→Img1, k1→Img20, k4→Img2 ...）。
4. 坐标文件含中日文**分组标题行**（`【すかし２】【Thread】【IR 1】…`），共 17 组，须跳过，有效区域 1880 个。
5. `M1_200217_094653MarinerFormat.dat`（早期那份）解析死循环 —— 它是"196608 头 + 连续数据"的非块链格式，CheckFile 不适用，已用新 `2A_DA.dat`（块链格式）替代。

**产物**（全部写入 `poc/`，遵循六角色规范：logging 毫秒格式 + try-catch + 常量提取）：
- `poc/parse/mariner_reader.py` — 块链遍历 + MM1_Side 提取 + 波段还原（复刻 CheckFile + ReadImgDataNew）
- `poc/parse/readzfile.py` — 坐标文本解析（复刻 ReadZFile，兼容全角逗号，跳过分组标题）
- `poc/run_poc.py` — 驱动脚本，输出 `global_onedat`(bin) / `wave_stats`(json) / `areas`(json)
- `poc/tests/test_poc_parse.py` + `tests/data/poc_parse_cases.json` — 数据驱动测试

**验证结果**：`python -m unittest tests.test_poc_parse -v` → **Ran 8 tests in 0.088s, OK**
（覆盖：record0 提取 213096 字节 / record 越界返回 None / 文件不存在抛异常 / 13 波段值 0-255 / 1880 区域 / 分组标题跳过 / 块大小一致性）

# 2026-08-19（续3）— 原版导出 S2 对拍基准操作指南

用户问"如何在原版 exe 上导出 S2[1..32] 作为对拍基准"。逆向 `release/SINGAN2.exe` 相关源码，确认导出链路并固化操作指南到 `docs/09_原版导出S2对拍基准操作指南.md`。

**核心代码事实**：
- 数据加载：拖拽 `.dat` 到主窗口"数据1区域" → `WM_DROPFILES`(WinMain.cpp:3501) → `DropDlg`(:348) → `MainRun` 自动算全部枚。
- 坐标加载：`ReadZFile`(ZAHYO_READ.CPP:16) 用 `Zfilename_[global_Z_No]`，来源主界面 `IDC_Z_COMBO` 下拉框（`File_Hensyu.cpp` 列表编辑对话框填入）。
- 币种：`IDC_COMBO_COUNTRY`(SProc.cpp:91)，必须选对 2A_DA 对应国家，否则 S2 基准无效。
- CSV 导出："View All Result" 按钮(IDC_BUTTON_GR, WinMain.cpp:1219) → `getCSVFileName`(:3694) → `a.csv`。
- CSV 列：第1列=枚号，第2~33列 = S2[1..32]（Ren.cpp:377 填充；WinMain.cpp:1230-1236 写出）。

**关键风险（实测修正）**：
1. `release/singan2.si2` 是空模板（坐标段=说明文字、函数名=`***/**/***`），坐标/币种不自动加载，须界面手动设。
2. **坐标格式兼容（实测验证通过）**：`ReadZFile`(ZAHYO_READ.CPP:60) 校验前 12 字节 == `【すかし１】`(`817982b7 82a9 82b5 8250 817a`)，`X_ATB_ZAR` 头部正是此串 → magic 通过，能加载（此前误判为"不兼容"已纠正）。
3. **结构高度兼容**：`X_ATB_ZAR` 26 个分组标题 ↔ ReadZFile 硬编码段（すかし1/2、Thred、Sekigai1-3=IR、Yogore=Soil、Horo=Hologram、old_sukasi、etc1-10）；段间跳过逻辑把 `【】` 标题行当分隔吃掉 → 数据对齐。
4. **前提：必须选对币种（最关键）**：`dNumber=Global_Dem*4`，`X_ATB_ZAR` 每组多为 72 行 → 需选 `Global_Dem=18` 的国家；选错则各段错位、S2 无效。
5. **已知轻微异常（不影响主线）**：`ETC10` 组 80 行（其余 72），因 `etc10` 是 ReadZFile 最后段，溢出 8 行被丢弃；`ETC11-17` 无对应段（只读 etc1-10），对应 ETC 特征 S2 可能为空，但前段主特征不受影响。

**待用户确认**：2A_DA 对应国家（需 Global_Dem=18 → dNumber=72）、a.csv 行数=总枚数、前段 S2 是否合理。

# 2026-08-19（续4）— 重要修正：ATB 坐标文件应为 `.bin` 而非 `.txt`

用户提供截图显示"Load ATB"按钮弹出的文件选择对话框过滤 `ATB File(*.bin)`，选中的是 `X_ATB_ZAR_132006050001.bin`。
这说明**之前把 ATB 坐标与 `.txt` Z 参数坐标混为一谈是错误的**。

**实际链路修正**：
- ATB 加载入口是 `WinMain.cpp:3020 LoadATB`（按钮 `IDC_BUTTON_LOAD_ATB`，见 `resource.rc:160`）
- 该函数直接 `fread(global_ATBS, sizeof(BYTE), sizeof(global_ATBS), fpr)`，文件选择对话框默认扩展名 `.bin`（`CFileAccess.cpp:132`）
- `global_ATBS` 定义在 `MAIN.H:507`：`global_ATBS[128][512 * 8]`，总大小 128×4096 = 524288 bytes
- `.txt` 文件属于另一套 `ReadZFile`/`global_Zparam` 路径，不是 ATB 路径

**已做修正**：
1. 重写 `docs/09_原版导出S2对拍基准操作指南.md`：步骤 0/2 明确使用 `X_ATB_ZAR_132006050001.bin`；删除所有关于 ReadZFile/.txt 的不当描述；更新风险与待确认项。
2. 重写 `docs/03_文件格式与数据结构.md` 第 4 章：区分 4.1 `.txt` Z 参数文本 与 4.2 `.bin` ATB 二进制，给出 `.bin` 8 字节区域布局及与 `.txt` 的对照表。
3. 新增 `docs/03_文件格式与数据结构.md` 9.3：ATB bin 解析层接口（基于验证脚本 `poc/tools/_atb_reader.py`）。
4. 新增验证脚本 `poc/tools/_atb_reader.py`：按 `global_ATBS[128][512*8]` 完整解析 `.bin`，实测 `X_ATB_ZAR_132006050001.bin` 524288 bytes、31 个非空 security、仅 face0 有数据。

**后续影响**：算法层推进时，POC 驱动脚本的 `--zfile .txt` 可能需要改为 `--atb .bin`，具体取决于 `C_SI2`/`Ren.cpp` 实际使用 `global_Zparam` 还是 `global_ATBS`；目前倾向 `global_ATBS`（因为界面 Load ATB 是 .bin）。
