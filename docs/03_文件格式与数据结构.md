# 03_文件格式与数据结构

## 1. 配置文件 `singan2.si2`

位于 EXE 同目录，文本格式，`S_load()/S_save()` 读写，保存内容大致包括：

- 上次使用的数据文件路径（`.dat` / `.txt`）
- 币种选择 `global_SelectCountry`、面额
- 坐标文件（.bin.txt）路径与选择
- 图像类型（Tab）、显示参数（对比度/亮度）
- V5 后新增：ATB / CTB / VTB 相关配置字段

> 兼容性：旧版 `singan2.si2` 不含 ATB/CTB/VTB 字段，新版程序解析时会抛异常，需更换新配置。

## 2. 图像数据文件（MarinerFormat `.dat`）

由钞票扫描仪输出，`CDataHeader` / `CTemplate` / `CTemplateData` 系列负责解析。

> **M0 验证说明**：以下小节 2.1 / 2.3 / 2.4 中的尺寸、块布局、波段映射均已通过
> `poc/parse/mariner_reader.py` 对 `2A_DA_111017_115542.dat` 实测验证（测试全绿），
> 取代原"推测"字段。实测样本为**标准块链格式**（非早期的 `M1_200217_094653MarinerFormat.dat`
> 连续数据格式，后者会导致 `CheckFile` 死循环，已被替换）。

### 2.1 文件头（CDataHeader / CTemplateData）

| 偏移 | 字段 | 含义 | 实测值（2A_DA） |
|---|---|---|---|
| 0–3 | `dataSize` | 块头 4 字节小端，本块总字节数（含头） | 随块变化 |
| 4 | `imageType` | 块类型枚举（见 2.3） | Head1=0 … |
| 5–31 | 保留 | 块头其余字节（`sizeof(CDataHeader)=32`） | — |
| 12–15 | `imageWidth` | 图像宽（**实测恒为 0**，尺寸硬编码） | 0 |
| 16–19 | `imageHeight` | 图像高（**实测恒为 0**，尺寸硬编码） | 0 |

> 关键修正：图像尺寸**不**从文件读取，而是硬编码为 `Y_SIZE=88 × X_SIZE=186`（见 2.4 常量表）。
> `dataCount`（总枚数）由 `CheckFile` 遍历块链统计得到，不在固定偏移。

`CheckFile()` 依据块头 `dataSize` 累加 `offset` 遍历整链；`ReadImgDataNew()` 用记录号/块类型定位并 `memcpy`
出 `global_onedat`。

### 2.2 波段（通道）类型

| `imageType` | 枚举名（实测） | 块字节数（实测） | 位深/说明 | 全局缓冲（例） |
|---|---|---|---|---|
| 0 | Head1 | — | 文件头 | — |
| 1 | Head2 | — | 文件头 | — |
| 2 | MM1Yose | — | 拼合信息 | — |
| 3 | MM8_Img | — | 8 波段大图 | `global_oneimg` |
| 4 | MM1_Img | 24504 | **16bit/像素**灰度（值有效，不进 S2 主路径） | — |
| 5 | **MM1_Side** | **16392** | **8bit/像素**，S2 算法输入（数据 16368 + 填充 24） | `global_onedat` 内波段 |
| 6 | Magnetic | — | 磁 | `global_oneimg_MAG` |
| 7 | Thickness | — | 厚度 | `global_oneimg_THICK` |
| 8 | UV | — | 紫外 | `global_oneimg_UV` |
| 9 | HEAD_SRU | — | SRU 头 | — |
| 12–18 | SRU_* | — | SRU 系列 | `global_oneimg_SRU` |
| 99 | Other | — | 其它 | — |

> 实测结论：**S2 算法输入是 `MM1_Side`（`type=5`），8bit/像素**，不是 `MM1_Img`（16bit）。
> 每枚记录含 `WAVE_COUNT=13` 个 MM1_Side 块，拼成 `global_onedat`（213096 字节）。
> 每枚记录最多约 2500 张（50MB 堆栈限制）。

### 2.3 块链布局（实测，复刻 CheckFile）

```
文件 [可选 3 字节 "SRU" 前缀] → 块0(32B头 + data) → 块1 → ... → 块N
块头: dataSize(LE uint32) @0..3, imageType(uint8) @4
遍历: offset = (3 if 以"SRU"开头 else 0); while offset+32<=n: 读块; offset += dataSize
死循环保护: dataSize<=0 立即 break（早期 MarinerFormat 连续格式会触发）
```

### 2.4 图像尺寸与关键常量（硬编码，已验证）

| 常量（mariner_reader.py） | 值 | 含义 |
|---|---|---|
| `Y_SIZE` | 88 | 图像高度（行） |
| `X_SIZE` | 186 | 图像宽度（列） |
| `ONESIZE` | 16368 | 单波段像素数 = 88×186 |
| `SIZE_NON_GBVX` | 24 | 每波段间填充字节（GBVX） |
| `MM1_SIDE_BLOCK` | 16392 | 单 MM1_Side 块 = ONESIZE+24 |
| `WAVE_COUNT` | 13 | 每枚 MM1_Side 波段数 |
| `BLOCK_HEADER` | 32 | `sizeof(CDataHeader)` 块头字节 |
| `GLOBAL_ONEDAT_SIZE` | 213096 | 单枚 `global_onedat` = MM1_SIDE_BLOCK×13 |

## 3. 除法表 `GBV_DIV_H.bin`

- `w_Table[8192]`：8192 项 16 位查表数组，用于 **Rute 整数开方**（`bvmath.cpp` 的 `Rute`）与速度校正。

## 4. 坐标文件（区域参数）

> 项目里存在**两套**坐标/区域文件：`ReadZFile` 读取的 `.txt`（Z 参数文本）和 `LoadATB` 读取的 `.bin`（ATB 二进制）。
> 二者用途、格式、加载入口完全不同，POC 算法层需区分清楚。

### 4.1 Z 参数文本文件（`.txt`，`ReadZFile` 读取）

> 实测样本 `X_ATB_ZAR_132006050001.txt` 为 Shift-JIS 纯文本，由 `poc/parse/readzfile.py` 验证解析（1880 个有效区域）。
> 该文件**不是**界面 "Load ATB" 按钮加载的文件；它进入 `ZAHYO_READ.CPP:ReadZFile` 填充 `global_Zparam`。

- 扩展名：实测为 `X_ATB_*.txt`（参考 `X_ATB_LSC_...`、`X_ATB_ZAR_...`、`X_ATB_DOP_...`）。
- 表头（第 1 行，含日文列名，解析时跳过）：
  `開始X,開始Y,終了X,終了Y,A閾値下限,A閾値上限,B閾値下限,B閾値上限,処理画素数`
  （对应 9 列：左上 X/Y、右下 X/Y、A 阈值下/上、B 阈值下/上、处理像素数）。
- 数据行：逗号分隔（兼容全角逗号 `，` / `、`），每行一个矩形区域 + 阈值。
- **分组标题行**：文件内穿插多个中日文分组标记（`【すかし１】【すかし２】【Thread】【IR 1】…`），
  首列为非数字，解析时须跳过（原 `ReadZFile` 据此切换 `global_Zparam` 的各段）。

#### 4.1.1 区域数据结构（POC 已验证）

```python
# readzfile.parse_zfile 返回的每个区域 dict
{
    "x1": int, "y1": int,       # 开始X, 开始Y（左上）
    "x2": int, "y2": int,       # 终了X, 终了Y（右下）
    "a_low": int, "a_high": int,   # A阈值下限 / 上限（实测对应 A/B 波长的二值化/微分阈值）
    "b_low": int, "b_high": int,
    "area_min": int,                # 处理像素数（area）
}
```

### 4.2 ATB 二进制文件（`.bin`，`LoadATB` 读取）

> 实测样本 `X_ATB_ZAR_132006050001.bin` 大小 524288 bytes，是界面 "Load ATB" 按钮直接加载的格式。
> 入口：`WinMain.cpp:3020 LoadATB` → `fread(global_ATBS, ..., fpr)`。

- 文件总布局：`global_ATBS[128][512 * 8]`（`MAIN.H:507`）
  - 共 **128 个 security**（ATB 类型索引 0..127）
  - 每个 security = **512 denos × 4 faces × 8 bytes = 4096 bytes**
  - 文件总大小恒为 `128 × 4096 = 524288 bytes`
- 每个区域（`area[8]`，`OnDrawPaint.cpp:80`）的 8 字节布局：

| 偏移 | 字段 | 类型 | 说明 | 与 `.txt` 对照（样本 area0）|
|---|---|---|---|---|
| 0 | `x1` | uint8 | 左上角 X | txt: 8 |
| 1 | `y1` | uint8 | 左上角 Y | txt: 22 |
| 2 | `width` | uint8 | 宽度 = `x2 - x1` | txt x2=36 → width=28 |
| 3 | `height` | uint8 | 高度 = `y2 - y1` | txt y2=42 → height=20 |
| 4 | `a_threshold` | uint8 | A 波长二值化阈值 | txt: 50 |
| 5 | `a_diff_threshold` | uint8 | A 波长微分阈值 | txt: 0 |
| 6 | `b_threshold` | uint8 | B 波长二值化阈值 | txt: 70 |
| 7 | `b_diff_threshold` | uint8 | B 波长微分阈值 | txt: 0 |

> `area_min`（处理像素数）不在 `.bin` 中存储，运行时按 `width × height` 计算。
> `.txt` 末尾的 `処理画素数` 列相当于这个运行时值（560 = 28×20 ✓）。

- 坐标访问公式（`OnDrawPaint.cpp:94`）：
  ```cpp
  memcpy(area,
         global_ATBS[selectSecurity] + ((deno * 4 + faceToShow) * sizeof(area)),
         sizeof(area));
  ```
  - `selectSecurity`：ATB 类型索引（0-based），如 `0=WM1`、`2=Thread`、`3=IR1`、`7=Dirt`、`8=Hologram` 等（见 `WinMain.cpp:3100 GetATBAreaName`）
  - `deno`：面额索引 0..127
  - `faceToShow`：0=A 面、1=B 面、2=C 面、3=D 面

- 当前 `X_ATB_ZAR_132006050001.bin` 实测分布：
  - 非空 security 仅 31 个（索引 0–25 及 112–116），其余全 0
  - 每个非空 security 内**仅 face0 有数据**，face1–3 全 0
  - 说明该坐标文件只定义了 A 面特征区域

### 4.3 两套坐标的区别（必读）

| | `.txt` Z 参数 | `.bin` ATB |
|---|---|---|
| 加载按钮 | 菜单 `Re-Load Coordinate` | 按钮 `Load ATB` |
| 加载函数 | `ZAHYO_READ.CPP:ReadZFile` | `WinMain.cpp:LoadATB` |
| 内存目标 | `global_Zparam` | `global_ATBS[128][4096]` |
| 格式 | Shift-JIS 文本，9 列 | 二进制，每区域 8 bytes |
| 坐标表示 | `x1,y1,x2,y2` | `x1,y1,width,height` |
| 阈值列 | A低/A高/B低/B高 | A阈值/A微分/B阈值/B微分 |
| 存储像素数 | 是（第 9 列） | 否（运行时算） |

> 导出 S2 对拍基准时，必须使用 `.bin` ATB 路径；`.txt` 不进入 S2 主计算流程（至少不通过 `LoadATB`）。
> `InitAll32()` / `Change_Look.cpp` / `Chia.cpp` 等若引用 `global_Zparam` 则可能用 `.txt`，需后续读算法层确认两套坐标的实际分工。

### 9.1 `parse/mariner_reader.py` — `.dat` 数据解析层

#### 9.1.1 常量（模块级，已对齐原工程）

见 2.4 常量表：`Y_SIZE=88, X_SIZE=186, ONESIZE=16368, SIZE_NON_GBVX=24,
MM1_SIDE_BLOCK=16392, WAVE_COUNT=13, BLOCK_HEADER=32, GLOBAL_ONEDAT_SIZE=213096`。
块类型枚举 `ENUM_IMAGE_TYPE`（dict: int→str）与 `WAVE_TO_IMG`（dict: k→Img名）见 2.2 / 2.5。

#### 9.1.2 函数接口

```python
def parse_blocks(file_path: str) -> List[Tuple[str, int, int, int]]:
    """遍历 .dat 块链，复刻 CheckFile。

    参数:
        file_path: .dat 文件路径
    返回: 块列表，每项 (type_name:str, type_id:int, data_size:int, data_offset:int)
    异常: 文件不存在/读失败抛 IOError（已被 try-catch 包裹并 log.error + traceback）
    死循环保护: data_size<=0 时 break
    """

def extract_mm1_side(file_path: str, record_index: int = 0) -> Optional[bytes]:
    """提取指定枚的 MM1_Side 数据，拼成 global_onedat(213096 字节)。

    参数:
        file_path: .dat 路径
        record_index: 枚索引（0-based），每 WAVE_COUNT=13 个 MM1_Side 块组成一枚
    返回:
        bytes(213096) 成功；record_index 越界或块长度异常返回 None
    异常: 文件读失败抛 IOError（已包裹 log.error）
    """

def build_onebyte_images(global_onedat: bytes) -> Dict[str, bytearray]:
    """按 ReadImgDataNew 的 memcpy 布局，从 global_onedat 还原 8bit 波段图像。

    参数:
        global_onedat: extract_mm1_side 返回的单枚缓冲（必须 213096 字节）
    返回: dict {img_name: bytearray(16368)}，仅含 WAVE_TO_IMG 定义的 13 个波段
          长度不符时返回空 dict 并 log.error
    """
```

#### 9.1.3 数据结构

| 名称 | 类型 | 说明 |
|---|---|---|
| block tuple | `(str, int, int, int)` | `(type_name, type_id, data_size, data_offset)` |
| `global_onedat` | `bytes[213096]` | 单枚 S2 输入缓冲：13×(16368 数据 + 24 填充) |
| onebyte image | `bytearray[16368]` | 单波段 8bit 灰度图，值 0–255，尺寸 88×186 |

### 9.4 `run_poc.py` — 驱动脚本（串联 + 产物输出）

#### 9.4.1 命令行接口

```
python run_poc.py --dat <dat路径> --zfile <坐标txt路径> [--record 0] [--out <输出目录>]
```

### 9.5 日志与错误处理约定（全解析层统一）

- 日志格式：`[%(asctime)s.%(msecs)03d] %(levelname)-5s %(name)s:%(lineno)d  %(message)s`
- 每个公开函数体均 `try-catch`，`log.error("... 异常: %s\n%s", exc, traceback.format_exc())` 后 `raise`，禁止吞异常。
- 文件日志初始化失败仅 `log.warning`，不影响主流程（见 `run_poc.init_logger`）。
- 所有魔法数字提取为模块级 `UPPER_SNAKE_CASE` 常量，禁止硬编码。
